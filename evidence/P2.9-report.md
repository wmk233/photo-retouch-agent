## 一、CropAndStitch 只读审计

上游: `https://github.com/lquesada/ComfyUI-Inpaint-CropAndStitch`，LICENSE **GPL-3.0**（仅审计，未 vendor 任何代码）。
证据: `evidence/p29-cropandstitch-audit/`（`upstream-README.md` / `readme-api.json` / `tree.json` / `inpaint_cropandstitch.py` 2036 行）。

两个节点构成一个契约:

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| `InpaintCropImproved` | `image`(必填)、`mask`(可选)、`optional_context_mask`(可选) + 若干技巧参数 | `(stitcher, image, mask)` |
| `InpaintStitchImproved` | `stitcher` + `inpainted_image` | 拼回原图的结果 |

关键参数: `mask_fill_holes`(True)、`mask_expand_pixels`、`mask_blend_pixels`(32)、`mask_hipass_filter`(0.1)、`extend_for_outpainting`、`context_from_mask_extend_factor`(1.2)、`output_resize_to_target_size` / `output_target_width|height`(512)、`output_padding`(32)、`device_mode`(`cpu (compatible)`)。

**已核实为真的三点**: 未选中区域不被改动（README 明说不经过 VAE encode/decode）；只编辑 mask 区域；裁剪 → 预缩放 → 采样 → 自动混合拼回原坐标。

**我们已有 / 我们还没有**:

- 已有: 原图、`mask`（hair / clothing 两张严格二值 0-255）、prompt、negative prompt、保护区。
- 还没有: 引擎节点本身（ComfyUI 环境）、采样模型（checkpoint）、`output_target_width/height` 的目标尺寸策略。
- **`optional_context_mask` 不是保护区**: 源码里它与 `mask` 做**并集**用来扩大裁剪范围。把我们的 `protected_identity_mask` 喂进去只会扩大裁剪，保护不了脸。它只能当"上下文提示"用。

**适不适合"头发一次 + 衣服一次"两步局部生成**: 适合。两张 mask 都与保护区不相交（`protected∩edit = 0`），可各跑一遍；但两者**彼此在发/衣交界带重叠 79,864 px**，必须按声明的顺序串行（见 4.2），不能当两个独立任务。

**适配风险点**:

1. 上下文裁剪会包含脸部 → 云端/本地模型**可能**动到裁剪框内的面部像素；因此裁剪后必须保留"按原坐标回贴原像素"的校验（`app.domains.portrait.inpaint_verify`），这是 fail-closed 的。
2. mask 必须是**全不透明白 (255)**；灰色会让原图透过去（本项目 mask 已保证 0/255 二值）。
3. `output_resize_to_target_size` 若开启会把结果缩放到目标尺寸 → **不能直接当作"保脸成功"**，必须按原尺寸回贴并校验（本项目已在文档中写明这条红线）。
4. 边界融合 `mask_blend_pixels=32` 会在 mask 边缘做羽化，边缘一圈像素来自重绘而非原图 —— 需要人工目视确认边缘自然度（`VISUAL_ACCEPTANCE_PENDING`）。
5. ATR 解析在 512×512 上推理后上采样，发际线与衣领精度约几像素（`parsing_boundary_is_approximate`），付费前建议人工微调。
6. 两张 mask 在发/衣交界带重叠，**必须串行**：pass 2 的 `image` 输入必须是 pass 1 的输出。若把两步各自独立跑在原图上再合并，交界带会互相打架（见 4.2）。

**结论**: 适合作为下一步真实引擎候选 —— 因为它的输入契约与本项目已有的输出（原图 + 二值 mask + prompt + negative prompt）一一对应，且承诺不改未选中区域。风险集中在"裁剪框内包含脸"，而这一风险本项目已有 `restore_kept_pixels` 按原坐标回贴作为兜底。

### 4.1 Style ID 核对（本轮新增）

- 生产 planner（`backend/app/domains/portrait/stylist.py`）只有 **3 个 axis**：`urban_short` / `artistic_wave`（艺术感长发微卷）/ `bold_street`。
- **`ai_elegant_refined`（精致优雅风）不是 stylist 的 axis**，它是历史 AI 生成的一次性 plan（`data/jobs/job_45f7920ad505.json` 里确实写着栗子棕大波浪 + 深橄榄绿法式复古衬衫）；`ai_stylist._unique_plan_id` 会按 LLM 给的 slug 生成 `ai_<slug>`，换一张照片不一定复现。
- 因此 CLI 侧**不得用 `urban_short` 顶替**。正确的可复现 ID 是 `--style 精致优雅风`，等价 `--style artistic_wave`。
- **已知 gap（如实记录）**: `artistic_wave` 自带发色 `burgundy_brown`（酒红棕）、服装为「奶白/酒红/复古绿」法式复古、配饰为金色圈形耳环；与 job_45f7920ad505 的「栗子棕 + 深橄榄绿 + 眉线眼镜」并不逐项相同。本轮**没有臆造新 axis**，也没有改 planner 算法。

### 4.2 hair / clothing 重叠区归属（本轮新增）

- 重叠 79,864 px；bbox x[240,764] y[524,1078]（发梢/衣领/颈肩交界带），与 protected identity 交集 **0**。
- 依据 CropAndStitch 源码语义（`stitch_magic_im`: `blended = mask*image + (1-mask)*canvas`，`canvas` = **该步收到的 image 输入**，不是最初原图）：
  - 两步串行时，**第 2 步的 image 输入 = 第 1 步的输出**，所以**谁最后跑谁拥有重叠带的最终编辑权**。
- **决定（按用户要求优先评估「先服装、后头发」）**: 采用 **pass 1 = clothing → pass 2 = hair**。
  - 理由（基于源码，不是口味）：交界带是**发丝压在衣料上**的区域。若服装后跑，服装 prompt + 服装 mask 会把这一带重绘成布料，胸前大波浪发丝会被抹掉；若头发后跑，头发 mask 在这一带重绘发丝，遮挡关系（发在衣前）得以保留。
  - 与之配套：pass 2 的 image 输入写死为 `output of step 'clothing'`；`prompt_bundle.global_prompt`、`mask_scope.engine_order`、`engine_handoff.steps`、`overlap.hair_and_clothing.note` 四处**同口径声明**该归属，不再出现「两张 mask 彼此独立」的表述。
- 结论: 两张 mask **不能当作彼此独立、互不影响**的任务。它们各自与保护区不相交（可单独跑），但彼此在交界带重叠，必须按声明顺序串行执行。
